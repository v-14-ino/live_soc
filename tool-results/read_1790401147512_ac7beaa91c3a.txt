    84→    84→Architecture decision (the cross-process problem):
    85→    85→- The Next.js dev server (port 3000) and the monitor-service (port 3003) are SEPARATE processes; the in-memory `sessionManager` singleton cannot be shared.
    86→    86→- Chose **Option A** from the task spec: the mini-service is the SINGLE owner of `sessionManager`. Next.js API routes never touch `sessionManager` directly — instead they `fetch('http://localhost:3003/internal/...')` server-to-server. (Server-to-server fetches to absolute URLs are allowed; the system-prompt gateway rule about relative paths applies only to browser→backend calls.)
    87→    87→- The internal REST endpoints are NOT exposed via Caddy (Caddy only forwards browser requests tagged with `?XTransformPort=3003`, which the browser only sends for socket.io connections, not for `/internal/*`). So `/internal/*` is reachable only from localhost.

    89→    89→socket.io + REST coexistence on path `/`:
    90→    90→- Inspected `engine.io/build/server.js` `attach()`: with `path: "/"` the `check(req)` returns `true` for EVERY URL, so ALL HTTP requests would normally fall through to `handleRequest` → `verify()` → 400 BAD_HANDSHAKE for non-socket.io requests.
    91→    91→- Solved by registering a connect-style middleware via `io.engine.use((req, res, next) => { if (req.url.startsWith('/internal/')) { handleInternalRoute(req, res); return; } next(); })`. This runs BEFORE engine.io's `verify()`, so `/internal/*` requests are short-circuited before socket.io touches them. (Note: the engine.io cors middleware registered before ours still adds CORS headers to `/internal/*` responses; harmless for server-to-server calls.)
    92→    92→- socket.io options: `path: "/"`, `cors: { origin: "*", methods: ["GET", "POST"] }`, `pingTimeout: 60000`, `pingInterval: 25000` (matches the example in `examples/websocket/server.ts`).

    94→    94→socket.io client lifecycle (path `/`, single `'message'` event channel):
    95→    95→- On connect: emit `{ type: 'hello', sessionId: '', serverTime }` immediately. (`sessionId` is empty at hello time because no subscription yet — frontend should treat hello as a connection-ack only.)
    96→    96→- Client commands arrive as `socket.on('message', cmd: WSClientCommand)`. Handler dispatches on `cmd.type`:
    97→    97→  - `subscribe` — looks up `sessionManager.getActive(sessionId)`. If found: registers a per-socket callback via `sessionManager.subscribe(sessionId, cb)` that calls `socket.emit('message', msg)` for every broadcast; joins room `session:${sessionId}`; then sends an immediate burst so the client has current state: `session_status` → `assessment_update` → `kpi` → `network_activity` → last 50 `event` messages → last 50 `alert` messages → all current `offense_scenario` and `defense_scenario` messages. If not found: emits `session_status` with `status: 'stopped'` + an `error` message with code `SESSION_NOT_ACTIVE`.
    98→    98→  - `unsubscribe` — calls `sessionManager.unsubscribe(sessionId, cb)`, leaves the room, removes from per-socket subscription map.
    99→    99→  - `ping` — responds with `{ type: 'heartbeat', serverTime }`.
   100→   100→  - `pause_stream` / `resume_stream` — flips a per-socket `paused` flag (server keeps broadcasting; client handles visual pause). Sends a `log` message acknowledging.
   101→   101→  - Default (unknown command type) — emits `error` message. Exhaustiveness-checked via `never` cast.
   102→   102→- On `disconnect`: iterates the per-socket subscription map and calls `sessionManager.unsubscribe(sessionId, cb)` for each — guarantees no dangling subscribers that would `socket.emit` to a dead socket.
   103→   103→- Per-socket state stored in a `WeakMap<Socket, SocketState>` so it's GC'd when the socket is.
   104→   104→- Heartbeat interval: every 25s, `io.emit('message', { type: 'heartbeat', serverTime })` to all connected sockets.
